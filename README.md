# Code Doc Agent Web

Веб-прототип агентной системы для автодокументирования Python-кода.

Пользователь может подключить проект через GitHub или загрузить локальный проект ZIP-архивом, после чего задавать вопросы по коду в чате. Агент ищет релевантные части проекта через инструменты, получает подробности по найденным символам и формирует ответ на русском языке.

## Что умеет

- чат с продолжением диалога;
- загрузка локального проекта ZIP-архивом или папкой;
- подключение публичных и приватных GitHub-репозиториев;
- отдельный индекс для каждого диалога;
- поиск функций, классов и методов по индексу;
- текстовый поиск по проекту для маршрутов, конфигов и констант;
- получение подробностей по найденным символам;
- grounding финального ответа по evidence из инструментов;
- структурированный JSON-вывод по схеме;
- сохранение и удаление диалогов.

## Как работает пайплайн

```text
проект / GitHub / ZIP
→ построение code_index.json
→ вопрос пользователя
→ LLM вызывает инструменты
→ search_symbols ищет функции/классы/методы
→ get_symbol_details возвращает тело найденного символа
→ search_project_text ищет маршруты, конфиги, Depends, JSON/YAML/TOML
→ собирается evidence
→ финальный ответ переписывается строго по evidence
→ ответ показывается в чате
```

LLM не должна придумывать архитектуру. Если нужные данные не найдены в индексе или текстовом поиске, агент должен прямо написать, что информация не подтверждена найденными данными.

## Инструменты агента

- `search_symbols` — поиск функций, методов и классов по индексу.
- `get_symbol_details` — получение сигнатуры, параметров, пути и тела найденного символа.
- `search_project_text` — текстовый поиск по файлам проекта. Нужен для эндпоинтов, `APIRouter`, `Depends`, конфигурационных файлов и констант.
- `read_file_range` — чтение небольшого диапазона строк из файла, если результата текстового поиска недостаточно.

## Evidence grounding

После того как LLM сформировала черновик ответа, агент собирает evidence из результатов инструментов:

```text
- найденные символы;
- тела функций/методов;
- подтверждённые вызовы функций;
- выбрасываемые исключения;
- текстовые совпадения в файлах проекта;
- найденные упоминания конфигурационных файлов.
```

Затем черновик переписывается отдельным LLM-запросом с правилом: использовать только данные из evidence. Это снижает риск галлюцинаций вроде несуществующих `roles.yaml`, RBAC или `403 Forbidden`, если они не были найдены в проекте.

## Установка

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если PowerShell запрещает активацию окружения:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.\.venv\Scripts\Activate.ps1
```

### Linux / macOS

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Настройка `.env`

Скопировать пример:

```powershell
copy .env.example .env
```

Указать токен и модель:

```env
LLM_API_KEY=hf_твой_токен
LLM_BASE_URL=https://router.huggingface.co/v1
LLM_MODEL=Qwen/Qwen3-Coder-30B-A3B-Instruct
LLM_TEMPERATURE=0.1

AGENT_INDEX_PATH=code_index.json
AGENT_LOG_PATH=logs/agent_steps.jsonl
AGENT_MAX_STEPS=8
AGENT_SYSTEM_PROMPT_PATH=prompts/system_prompt.txt

GITHUB_TOKEN=
```

`GITHUB_TOKEN` нужен только для приватных GitHub-репозиториев.

Файл `.env` нельзя добавлять в Git.

## Запуск

```powershell
uvicorn web_app:app --reload
```

Открыть в браузере:

```text
http://127.0.0.1:8000
```

## Загрузка локального проекта

Самый удобный вариант на Windows — ZIP-архив.

1. Открыть веб-чат.
2. Создать новый диалог.
3. В блоке локального проекта выбрать `.zip`.
4. Нажать кнопку загрузки.
5. Дождаться построения индекса.
6. Задать вопрос по проекту.

Загруженные проекты сохраняются в `data/uploads/` и не попадают в Git.

## Подключение GitHub-репозитория

Для публичного репозитория достаточно ссылки:

```text
https://github.com/owner/repo
```

Для приватного репозитория нужен GitHub token. Его можно указать в `.env` или временно в интерфейсе подключения.

Склонированные репозитории сохраняются в `data/repositories/` и не попадают в Git.

## Пример вопроса

```text
опиши механизм ограничения доступа к эндпоинтам сервиса.
ответ структурируй в несколько разделов:
1) сначала общие принципы не более чем в пяти предложениях
2) какая используется модель прав, если это релевантно
3) как это реализуется в коде без примеров кода
4) что произойдет при попытке неавторизованного доступа
5) какие конфигурационные файлы отвечают за ограничение прав
```

Для такого вопроса агент должен использовать не только `search_symbols`, но и `search_project_text`, потому что часть информации находится в маршрутах и конфигурационных файлах.

## Логи

Логи пишутся в:

```text
logs/agent_steps.jsonl
```

В логах можно увидеть:

- начало turn;
- вызовы инструментов;
- результаты инструментов;
- auto evidence search;
- evidence bundle;
- grounded final answer.

## Что не попадает в Git

В `.gitignore` добавлены:

```gitignore
.env
.venv/
logs/
data/conversations/
data/repositories/
data/uploads/
data/indexes/
code_index.json
```

То есть токены, история диалогов, загруженные проекты, склонированные репозитории и индексы не коммитятся.
